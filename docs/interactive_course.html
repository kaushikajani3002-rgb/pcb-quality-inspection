PCB AOI System

Project Overview

Welcome to the team! This onboarding guide is your single source of truth for understanding the PCB AOI software infrastructure.

Why this project exists

Manufacturing PCB boards at scale introduces physical defects (missing parts, misalignments, solder cracks). Human visual inspection is too slow and error-prone.

The Problem it Solves

It automates Quality Control (QC) by taking a raw camera image of a PCB, aligning it, detecting components via Deep Learning, and mathematically verifying them against a master JSON layout.

Expected Users

Factory line operators monitoring the dashboard, and Quality Assurance managers reviewing the exported PDF certificates.

Input & Output

Input: High-res Camera Image
Input: Template JSON (Coordinates)
Output: PASS/FAIL UI State
Output: PDF/CSV Inspection Report

Current Implementation

The entire Streamlit UI, Configuration Loaders, Math Inspection Engine (Position/Missing/Extra checkers), and Exporters are built. The AI detection is currently simulated via a Mock Layer.

Future Implementation

Integration of real OpenCV homography for alignment, YOLOv11 for bounding box inference, and segmentation models for crack detection.

Runtime Execution Order

When the operator types streamlit run app/main.py, this is the EXACT chronological order of execution based on our project architecture.

1. main.py
↓
2. utils/config_loader.py

Loads tolerances (mm limits, confidence thresholds) from config.yaml

↓
3. utils/template_manager.py

Loads the JSON blueprint for the selected board.

↓
4. Wait for Operator Input

Operator uploads an image in Streamlit.

↓
5. mock/mock_results.py

Currently intercepts the image and generates fake YOLO bounding boxes for testing.

↓
6. inspection/inspection_engine.py

Executes Position, Missing, and Extra checkers against the mock data.

↓
7. utils/report_exporter.py

Saves the final discrepancy payload to PDF and CSV.

↓
8. Dashboard Updates

UI renders PASS/FAIL state and draws bounding boxes on the canvas.

End-to-End Data Flow (One Image's Journey)

Let's follow the data transformation of a single uploaded image.

1. Upload Image (UI)

Enters: Raw `.jpg` or `.png` byte stream.
Changes: UI holds the image in memory.
Leaves: Image bytes passed to validation.

↓

2. Detection Simulation (Mock Layer)

Enters: Image bytes.
Changes: System generates synthetic bounding boxes formatted exactly like YOLO output.
Leaves: Array of objects: [{"class":"IC", "bbox":{"x":0.5, "y":0.5}}]

↓

3. Inspection Engine (Core Logic)

Enters: YOLO array + JSON Template coordinates.
Changes: Engine calculates Euclidean distances in physical millimeters. Finds missing elements.
Leaves: Aggregated Dictionary containing `status: FAIL` and `discrepancies: [...]`

↓

4. Output & Reporting

Enters: Aggregated Dictionary.
Changes: Exporter formats data into a PDF. Streamlit UI updates its state machine.
Leaves: PDF saved to disk. Bounding boxes rendered visually on screen.

Current Architecture (What Exists Today)

The foundation is fully built and tested using a Mock-First approach.

The Decoupled System

Our architecture proves that the UI does not care where the detection data comes from. Currently, app/main.py receives data from mock/mock_results.py.

The inspection/inspection_engine.py successfully processes this simulated data and accurately generates PDF reports using utils/report_exporter.py.

This means the backend infrastructure is 100% ready to receive real AI models without needing to rewrite the UI or the Exporters.

Future AI Integration

This is where the real Computer Vision happens. When we move to production, we will delete the Mock Layer and plug in the following modules.

1. Industrial Camera Feed
↓
2. OpenCV Alignment (preprocessor.py)

Uses Homography to deskew the image to match JSON dimensions.

↓
3. YOLO Detection (detection_engine.py)

Replaces mock_results.py. Runs inference to find BBoxes.

↓
4. Defect Segmentation (DeepPCB)

Secondary models to catch microscopic thermal cracks.

↓
5. Plugs into existing Inspection Engine

Project Summary & Timeline

The complete end-to-end timeline of the PCB AOI System.

T=0s : Initialization

main.py boots Streamlit. Loads config & JSON templates.

T=1s : Image Upload

User uploads PCB photo. Passed to validators.py.

T=2s : Alignment (Future)

OpenCV straightens the image in preprocessor.py.

T=3s : AI Inference (Current Mock)

System gets bounding boxes via Mock Layer (or YOLO).

T=4s : Math Verification

inspection_engine.py loops through BBoxes. Checks mm distances.

T=5s : Report Generation

report_exporter.py builds PDF. UI renders final PASS/FAIL visual.
