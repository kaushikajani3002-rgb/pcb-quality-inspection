------------------------------------------------------------------------
1. CORE ARCHITECTURAL OVERVIEW
------------------------------------------------------------------------
The system has been built from the ground up following Clean Architecture and SOLID
principles. It decouples the visual components (Streamlit frontend) from the business
logic (Inspection Engine) and the data generation layer (Mock Prediction Layer).

No AI/ML libraries (like PyTorch, OpenCV, or Ultralytics) are imported to maintain a
zero-dependency, lightweight footprint. Instead, a robust simulator (Pillow canvas drawing)
and structured mock models mimic model responses, allowing the app to run out of the box.

3. WORK COMPLETED & IMPLEMENTED PATTERNS
------------------------------------------------------------------------

A. Device Dropdowns & Normalized Coordinates:
   - Configured exactly three device templates: Arduino Uno (14 critical components),
     ESP32 DevKit (9 components), and STM32 Blue Pill (10 components).
   - Switched from pixel-specific coordinate systems to normalized coordinate percentages
     (0.0 to 1.0) inside templates. This allows scaling calculations to any resolution.
   - Refactored distance evaluations to represent physical millimeters (mm) by multiplying
     percentages by the board's physical dimensions (width_mm × height_mm).

B. Streamlit Operator Dashboard (app/main.py):
   - Created a professional industrial visual interface.
   - Maintained an explicit session state machine (workflow status tracking: IDLE,
     PROCESSING, COMPLETED, ERROR).
   - Displayed board metadata (mm dimensions, names, list of critical components) dynamically.
   - Added a sidebar tolerance slider in millimeters (0.1mm to 5.0mm).
   - Integrated custom PASS/FAIL glowing status banners and tabular verify ledgers.

C. Exporter Factory Pattern (utils/report_exporter.py):
   - Outlined a polymorphic BaseReportExporter interface with JSON, CSV, and PDF concrete subclasses.
   - Generates ReportLab-based PDF summaries mapping inspection logs, operator IDs, expected stats,
     and tabular registers of anomalies (missing, misaligned, cracks, extra components) with 
     proper grid styling and color-coded statuses.

D. Input Pipeline Validators (utils/validators.py):
   - ImageValidator: Validates file sizes (<15MB) and inspects magic byte headers (signatures 
     for PNG vs. JPEG) to reject corrupt uploads.
   - ConfigurationValidator: Holds threshold values inside secure boundaries.

E. Logging Interface (utils/logger.py):
   - Structured logging writing all steps, warning anomalies, and errors to logs/inspection.log.
